# Nexmail goal prompts

Use these prompts as reusable task frames. Fill the short **Goal inputs** once, then let the prompt preserve requirements, architecture, cross-stack acceptance, and handoff expectations across the development task.

| Prompt | Use when |
| --- | --- |
| [PROJECT_GOAL.md](PROJECT_GOAL.md) | Starting or resuming the overall Nexmail project |
| [FEATURE_GOAL.md](FEATURE_GOAL.md) | Implementing any product feature end to end |
| [FEATURE_GOALS.md](FEATURE_GOALS.md) | Starting a named account, mail, compose, sync, search, settings, or portability feature |
| [PROVIDER_GOAL.md](PROVIDER_GOAL.md) | Adding or completing a mail provider adapter |
| [MILESTONE_GOAL.md](MILESTONE_GOAL.md) | Delivering a roadmap milestone |
| [COMPLETION_AUDIT_GOAL.md](COMPLETION_AUDIT_GOAL.md) | Checking whether a feature or release is actually complete |

The canonical scope and done state live in `PRODUCT.md`, `continuity.md`, and `RELEASE.md`. Prompts point there rather than copying the full specification, so the requirements have one source of truth.
